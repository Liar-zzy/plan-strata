# 0.2.0-alpha.1 — No-hash workflow / 无哈希工作流

2026-09-10 · dev prerelease · schema 2 · Python 3.10+

## What changed

Mandatory content hashes and the `fingerprint` command are removed from the skill,
templates, validator, and current evaluation tools. Checks list subject/evidence
paths; task bindings use versioned plan paths. No extra commit or full-workspace
snapshot is required for ordinary bookkeeping. Existing Git versions/diffs remain
useful when available, but Git is optional.

Validation explicitly reports `validation_scope: structure_only`. The old
`overall: verified` becomes `overall: accepted`: this describes recorded acceptance,
not verified program behavior. The helper does not read artifact contents, detect
content changes, discover omitted inputs, judge test coverage, or authenticate logs.
After relevant changes, Manager explicitly reopens affected acceptance, reruns
affected checks, and writes a new check while preserving earlier evidence.

Parallel handoffs remain off by default, enabled only for an explicitly authorized
batch. Issue bodies remain executable task briefs with accessible inputs, ownership,
scope, budget, acceptance, and return instructions. Removing digests does not remove
dependency readiness, isolated writes, single-Manager progress, or final integration.

## 升级与兼容性

这是不兼容的预览版更新，不是仅修改宣传文案：

- 新记录统一 `schema: 2`；subjects/evidence 是非空路径字符串列表。
- 删除 `core_sha256`、`plan_sha256` 及任务内的哈希绑定，不提供轻量/严格双模式。
- 输出 `structure_only` 与 `accepted`，不再承诺自动发现验收后发生的内容变化。
- 旧 schema 1 或混合活跃记录会返回 `UNSUPPORTED_SCHEMA`；只改数字也不是迁移。

保留历史记录。正在进行的旧迭代可以继续使用匹配的旧技能/校验器；或先明确交接
并处理运行中任务，再从新模板创建新迭代、版本化 core 和计划，显式切换 CURRENT。
复用旧交付时重新判断其适用性并写新检查，不覆盖历史 verdict。旧记录不再被当前
入口引用时，可以继续留在仓库，不会阻止新协议校验。

当相关源码、测试、配置或数据改变时，先把受影响任务置为 `needs_review`，将不再
适用的 `integration_check` 清为 null，并在进度正文保留旧检查引用；实际复测后
新增检查再接受。无关修改不必重开。无人修改代码也不代表检查自动充分：遗漏入口、
旧日志与错误验收方法仍可能存在，须靠真实测试和范围审阅解决。

## 获取这个版本

此版本面向 `dev`，不合入 `main`，也不建立 GitHub Release。仓库简写安装仍取远端
默认分支，不会自动选择 dev。从目标项目安装 dev（已实际验证）：

```sh
npx --yes skills@1.5.23 add https://github.com/Liar-zzy/plan-strata/tree/dev --skill plan-strata --agent codex --yes
```

也可以把 URL 换成已审查的 dev checkout 绝对路径。这是项目级安装，已有同名技能先备份本地修改，
去掉末尾 `--yes` 可查看提示。无需 Node 的手动复制方式见中英文 README；仓库推送
不会升级你的已安装副本。本轮不改动全局技能。

## Remaining limits / 剩余边界

Structural consistency is not task correctness. Acceptance still depends on actual
verification, appropriate scope, and honest reports. The skill does not enforce
budgets, provide atomic claims or cancellation, or implement an agent scheduler.
No new claim is made about production concurrency, fewer human interventions,
real research outcomes, client discovery, or cross-client agent behavior.

本轮采用 skill-creator 的最小化原则与 writing-for-agents 的指令写作约束：明确删除
自动内容校验承诺，提供一套 v2 默认流程和简短的显式复核动作，不增加模式开关、
新状态、预算引擎或调度平台。历史 P001–P008 及旧评测结果按当时语义保留。
