# Issue 独立接手 — 本地冷启动验证

日期：2026-09-07；范围：[P007](../plans/ex-plans/P007/ex-plan-v0.1.0.md)，起始 dev
为 abe41f2。保持 alpha.2、并行默认关闭、protocol v1 与只读校验器不变。
使用 `skill-creator` 的真实产物验证原则，以及 `writing-for-agents` 的明确完成条件
和按需披露原则：规则集中在交接参考中，入口只补路由，模板不新增机器字段。

## 本轮补齐的契约

- 所选渠道就是完整任务单。Issue 正文包含目标、边界、开工条件、验收及返回要求；
  详细计划可引用固定且可访问的版本，不能依赖 Manager 未交付的本地文档。
- 区分任务说明完整、依赖就绪和实际领取。允许先发布完整但未领取的任务；领取时
  确认 owner、attempt 与工作区，不再等待补核心任务说明。阻塞任务明确释放条件。
- 在派发前从接收者入口检查实际快照；固定 Git commit 与可获取 ref、材料及指纹。
  保留领取快照，Worker 核对绑定和分配后创建隔离工作区，Manager 仍独占进度与接受。

这是针对用户描述的入口缺口的局部修复。没有原 Issue 和当时的技能版本，因此未
重放原案例，也未对旧/新技能进行同请求对照；不能量化成功率提升或断言原案例唯一根因。

## 场景与上下文边界

[复跑步骤](../evals/README.md#issue-cold-start-trial)和
[场景准备器](../evals/issue_trial.py)保留在仓库评测区，不随技能安装。
准备器创建本地 bare Git 源，先冻结源文件与计划，再推进默认分支；保留
`trial-baseline` 标签指向原提交。它不准备 Worker 目录、不生成 Issue 正文、不启动 Agent。

新上下文作者只收到技能、原始项目和用户请求，生成 T01（实现求和）与 T02（依赖
已接受实现的文档）两份 Issue。root 曾发送进度与简短输出提醒，未提供期望正文、
实现或评分规则。作者验证可获取的固定基线，给 T01 写出完整任务、创建工作区的方法
与返回契约；T02 明确阻塞在实际交付、通过 check 和 Manager 释放上。

root 检查正文后登记领取，只加入分配回执，不补核心任务。Worker 使用新上下文，
仅收到技能入口及包含回执的 Issue 快照，可以读取其中引用的材料。这里的独立性
指上下文隔离，不是文件系统安全隔离、不同模型或统计独立样本。

## A01 的实际失败与恢复

root 错将内存中的早期正文草稿与作者最终精简正文的指纹拼接，形成错误领取快照。
Worker 在入口核验发现正文指纹不一致后停止：没有创建工作区、写代码或执行测试。
root 的独立归档校验也触发同一不匹配，检查确认最终正文为 6359 字节，旧缓存为
8265 字节；不是换行差异，也不是缺少任务说明。

这是评测组织者的快照错误，不是修改后技能的已证实缺陷。保留
[失败归档](../evals/results/issue-author-001.json)及
[停止与恢复记录](../evals/results/issue-cold-start-blocked-001.json)。失败归档的 Issue
`sha256` 是当时声明值，与其中旧正文不符，不能作为成功的内容指纹验收。
旧 Worker 已结束且无残留作业；root 重新读取已冻结的最终文件，为新 Worker 分配
A02。派发前核对完整保留正文与最终文件逐字节相等，并核对 SHA-256。

[更正后的作者产物与 A02 领取快照](../evals/results/issue-author-002.json)保留两份最终
Issue、七份初始项目文件、原始请求及分配记录，所有内容指纹已实际核对。
复跑说明补充：等待作者完成后，从实际保留的同一份字节计算指纹，避免混用缓存草稿。

## A02 接手结果

新 Worker 自行创建 source clone 和独立 workspace worktree，HEAD 为指定的
`659e5b8999440c06d3eb22ec86096e0ce6ca4f01`，而非前移后的默认分支
`6dfc571e3f53f0ec2160902db658870e50660747`。它核对了 Issue 正文指纹、Manager
领取确认和初始输入，不需要另补任务说明。实现后一次运行全部 3 项测试通过，
随后留下报告、基线观察、实际测试输出及 scoped diff，回交 root 并结束。

root 在 Worker 结束后重新读取实际文件，核对五份改动/新增产物的指纹，确认六份
其他基线文件（包括 Worker 副本中的 progress）原样保留；检查真实 worktree 登记
及 Git HEAD，并独立重跑同样 3 项测试，通过且退出 0。Worker 一次、Manager 一次，
共两次行为验证，未超过该尝试的三次额度。没有额外任务执行或后台作业。

[Worker 完整快照](../evals/results/issue-worker-A02-001.json)保留技能指纹、实际源码、
报告、命令与结果；[root 的最终复核](../evals/results/issue-cold-start-review-001.json)
记录独立运行和实际范围检查。root 曾提醒简短收尾，未补充实现或预期答案。
临时路径作为历史来源保留，证据依赖仓库内完整捕获的文字和指纹。

结论：一次“完整未领取 Issue → 领取登记 → 新 Agent 从零创建 worktree → 执行与
回交”的本地链路通过。A01 另提供一次输入不一致时的实际安全停止观察，不把它算作
成功执行，也不隐去组织者错误。Worker 副本元数据为 consistent/open；Manager
将合成项目 T01 保留为 needs_review，未创建其接受 check 或释放 T02。本轮验收的是
P007 的交接能力，不是把这个两任务合成项目宣布全部完成。
