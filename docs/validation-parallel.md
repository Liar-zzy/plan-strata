# 0.1.0-alpha.2 — 可选并行交接试用

> 本文记录首次试用的历史快照。后续审查发现接收端基线漂移和 `integration`
> 任务标识冲突；修复及当前源码的验证见[后续回归记录](validation-handoff-fixes.md)。
> 下文的 35 项测试和 Agent 快照不能作为修改后版本的新行为试用证据。

日期：2026-09-07。范围：本地候选技能、一个双 Worker 合成开发场景、终验交接及回归检查。
未创建 Issue、commit、push、Release 或全局安装。复跑方式见
[评测说明](../evals/README.md#parallel-handoff-trial)。

## 最小实现

技能增加一个按需参考和两份可复制任务单，入口新增 5 行指引。默认流程、protocol v1、
状态字段、development/research 任务类型与只读校验器保持兼容。
渠道选择与任务契约分离：本轮使用本地文件，没有 Git 仓库、分支、Issue 或平台适配器。
Manager 判断任务是否就绪、维护唯一进度并调用实际宿主工具；技能没有获得自动调度能力。

终验沿用 integration_required/integration_check，不新增 review 类型或冗余的终验任务行。
科研分支补充总体预算、固定输入和方法一致性要求，本轮没有真实科研实验或科研并行试用。

## 实际独立接手

作者先准备冻结接口、输入、测试和任务单，再将两个隔离目录分别交给新的 Worker。
只提供技能快照、工作目录、任务单和接手请求，没有提供原对话、生成器、预期实现或评分规则。
两个 Worker 通过宿主分别启动并同时在运行，各自只修改一个模块及自己的报告/日志目录。
随后另一个新 Agent 接手终验；“独立”指上下文隔离，不代表不同模型或统计独立样本。

| 阶段 | 实际观察 | 保留证据 |
|---|---|---|
| T01/A01 | 实现字符串清洗；14 项基线匹配；指定测试运行 1 次通过；进度未改 | [Worker T01](../evals/results/parallel-worker-T01-001.json) |
| T02/A01 | 实现字符串拼接；14 项基线匹配；指定测试运行 1 次通过；进度未改 | [Worker T02](../evals/results/parallel-worker-T02-001.json) |
| Manager 收集 | 作者读取源码与两份报告；驱动按写入允许列表收集并重跑两项任务测试，任务 done，整体仍 open | 最终 Manager 快照保留该阶段的任务检查及日志 |
| Integrator/A01 | 核对 27 项固定输入，检查组合后的代码；完整测试 3/3 通过，运行 1/2 次；未改源码或进度 | [独立终验](../evals/results/parallel-integration-001.json) |
| Manager 最终交付 | 作者审阅终验报告与实际证据，收集建议检查；最终 consistent / verified，无错误或警告 | [Manager 最终快照](../evals/results/parallel-manager-001.json) |

终验任务的输入已由 Manager 按允许列表复制组合；Integrator 验证这个具体组合，
没有执行 Git merge、解决代码冲突或合入主分支。最终接受只针对样例的冻结接口与测试。
Worker 与 Integrator 副本的 overall 仍为 open，正确反映它们没有代替 Manager 接受整轮。

捕获文件保存技能指纹、实际文字产物、日志、检查和新运行的元数据校验结果。
临时路径作为历史来源保留，当前证据依赖仓库内捕获文件；Python 缓存不作为源码归档。
终验的基线观察曾额外记录缓存指纹，但其 check subjects/evidence 均有完整文字归档。

## 回归与兼容性

35 项检查在 Python 3.10.9 和 3.14.7 上通过，退出 0。分别保留
[Python 3.10 输出及源码指纹](../evals/results/parallel-py310-001.json)和
[Python 3.14 输出及源码指纹](../evals/results/parallel-py314-001.json)。
包含原有 20 项协议检查和新增 15 项试用驱动检查：

- 无 Git 的准备及基线固定；旧目录拒绝覆盖。
- 两项任务通过但未终验时保持 open；任务失败时不准备终验目录。
- 原样重复收集为 no-op；同一尝试变更、旧目标冲突、越界修改、删除或符号链接拒绝收集。
- Worker 不能替换 Manager 进度；只读终验不能夹带源码修复。
- 终验失败保持 open，失败证据保留；另一次已授权修复后的新检查可通过。
- 过期通过证据不能被接受；最终成功仍只能由 Manager 挂接检查。

其中失败、重试和修复由确定性测试注入，不是额外的独立 Agent 实验。
新增测试开发过程中曾因一段断言放错方法触发 NameError，修正位置后完整重跑；
上面归档的是修正后最终源码的 35 项结果，不宣称所有开发中间运行都成功。
技能格式校验使用临时 PyYAML 环境通过，见[契约审阅](evidence/P003-handoff-contract.md)。

## 观察与边界

任务单足以让接手者恢复边界、指纹、预算和返回要求，三个 Agent 都保留了 Manager
对进度的独占写入。此次没有暴露需要修改技能契约的阻塞，因此未额外增加补救规则。
试用驱动在终验前补齐了输入清单与任务单的归档，最终 Manager 可访问所有检查引用；
这个路径由回归测试覆盖。驱动只服务该合成样例，不随技能安装，也不适用于任意项目。

同时观察到记录成本：两个很小的函数也产生了基线、报告与验收材料。此次没有测量
净提速或维护成本收益，不能据此声称多 Agent 比串行更快。默认保持轻量，优先在已有
清晰接口且工作量足够的独立任务上选择此模式。

未验证跨 ex-plan 调度、自动依赖推断、GitHub Issue 同步、分支冲突处理、真实运行时
取消/重启、分布式锁、生产并发、真实科研效果、安装后的客户端自动发现或跨客户端行为。
下一步宜在真实项目的一次自然迭代中观察交接收益与记录成本，再决定是否需要渠道适配器。
