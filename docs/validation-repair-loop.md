## 改动与语义核对

`SKILL.md` 在任务预算/审核返修处指向按需加载的
[有限修复指引](../skills/plan-strata/references/repair-loop.md)，并将冻结 check 的
时机明确为验收决策。Worker 模板沿用现有预算字段，没有新增必填协议字段。
中英文 README 同步给出请求示例和约束。按 writing-for-agents 的渐进披露原则，
详细闭环放在参考文件，不将所有步骤塞入技能入口。

以下为 root 对实际指引、模板和既有协议的语义核对，不是独立 Agent 的运行观察：

| 场景 | 核对结果 |
|---|---|
| 范围内自检返修 | 保持一个完整任务；内部补丁不自动要求新阶段、报告、check 或人工审批 |
| 正式返回后修复 | Manager 在既有权限/总预算内继续；保留旧交付，确认旧写入者停止/隔离后分配新 attempt，不改写收到的结果 |
| 输入改变但仍通过 | 实际复核后形成新适用 check，保留旧输入与检查；仅改哈希不算验证 |
| 重复失败、预算耗尽或越界 | 先检查遗漏路径与反例；到边界保留未完成状态和具体决策，不无限续派 |
| 用户从 Issue 指定 Worker | 指定可以提供分配依据；默认开工前登记，延后同步需显式协调约定和可恢复独占分配，不能凭旧 planned 再派发 |
| 科研负结果与其他审核技能 | 有效负/不确定发现不触发“修到正结果”；Plan Strata 的可选 Reviewer 不覆盖其他已选技能的要求 |

交接说明仍要求实际就绪依赖、可取得的固定材料、独占写入、容量检查和 Manager
单一进度权威。此轮没有实现延后登记适配器、锁、调度器或新的自动派发能力。
