# P003 — 可选并行交接的最小闭环

## 范围与预算

以 0.1.0-alpha.2 本地候选版本添加与渠道无关的交接指导及模板。保持 protocol v1、
只读校验器和默认流程兼容；首版只覆盖同一已确认 ex-plan 的委派与最终集成关卡。
不实现自动任务执行器、跨计划依赖、GitHub 适配器或自动合入主分支。

允许一个合成开发场景中两个隔离 Worker 并行、一个独立 Integrator 接手，最多一轮
针对实际失败的修正复测；另用本地合约测试验证验收失败等路径。科研只检查管理约束，
不启动真实实验。无网络任务、全局安装、真实 Issue、commit 或 push。

## T01 — 协议与可复制任务单

输入：现有技能和本次用户确认。产物：按需读取的并行交接说明、Worker 与 Integrator
任务单模板、入口指针。验收：明确可选条件、任务就绪与隔离、绑定、单一进度维护、
结果证据、重复派发恢复、失败返工、科研总体预算以及外部权限边界。Issue 仅为渠道。
不以纯文本任务单冒充经过机器校验的调度状态。

## T02 — 闭环试用与双语入口

依赖 T01 的任务单契约。产物：可重建的隔离场景、回归检查、真实 Agent 试用证据、
中英文使用入口与验证记录。两名 Worker 接手不同文件和任务，各自提交产物与日志；
Integrator 在合成后的最终目录检查，Manager 独自更新权威进度并作交付决定。
验收：确认隔离范围、计划字节和进度未被 Worker 改写；最终集成通过才整体 verified。
回归测试还需覆盖集成失败、过期结果、同一结果重复收集的处理；保留失败证据。
运行原合约测试与新测试，Python 3.10/3.14 验证；报告真实覆盖和未验证部分。

## 集成验收与停止

统一检查最终技能包、模板、双语入口、试用产物和本轮记录的一致性；保留实际测试
输出和文件指纹。使用现有 integration_required/integration_check，不新增 review
任务类型。达到以上范围后交付本地修改和可复制试用方式，由用户决定后续发布。
