## T01 — 完整任务的有限修复闭环

补齐同一任务内实现、自检、有限返修的可执行规则与例子。明确内部补丁、正式交付、
验收检查和用户授权的边界；Manager 可在既有权限与预算内继续组织修复，不把 Worker
返回默认解释为必须等待人。保持已交付结果、失败检查和计划绑定可恢复；输入改变
时，即使结论仍为 pass，也需要新的适用检查。保留科研负结果与原有资源停止边界。

澄清开工前独占分配与进度记录的关系：默认仍先由 Manager 登记，不把 Issue 正文
和重复任务单分开。用户直接指定执行人可作为分配依据，但延后登记不是默认调度
能力，需要显式协调约定，不能凭旧 planned 状态重复派发。不新增协议状态、字段、
抢占锁、调度器或平台适配器，也不覆盖其他实际选用技能的要求。

保持 CLI 的现有退出码行为，修正 invocation/path failure 的歧义，并为非法或缺失
CURRENT、记录内路径错误、项目初始化失败、fingerprint 失败和参数解析补回归。
中英文 README 同步概括行为与限制，技能版本仍为 alpha.2，以提交或指纹区分 dev。

## 验收和停止边界

检查规则在内部自检返修、正式交付后返修、输入变化但仍通过、越界/预算耗尽、用户
直接领取及科研负结果下是否一致。新增确定性测试，运行实际小项目命令，验证同一
任务/计划内修复可接受、失败历史保留、过期证据不能继续接受；已有并行回归继续
验证同 attempt 改写拒绝。脚本安排的动作不冒充独立 Agent 的行为观察，不宣称已
测得人工中转或耗时下降。

运行完整 unittest（本地 Python 3.10 与 3.14）、技能格式检查和本仓库只读校验，
保留命令结果及被检文件指纹。允许范围内实现、自检及最多两轮最终检查后的返修；
接受标准、资源或权限需要变化时先报告。本次无需另设终验任务、独立 Reviewer 或
每补丁一个报告；最终检查适用后交付用户，未经新授权不提交或推送。
