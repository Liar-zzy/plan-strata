# Repair and delivery

Implementation, self-checks, and in-scope repairs belong to one observable outcome.
Continue within existing authorization until acceptance or an applicable stop;
a delivery or review finding is not automatically a new user approval gate.
Separate defects against agreed criteria from new requests.

Inherit user/host limits. Ordinary local repair needs no invented round count,
test quota, or budget ledger. Paid compute, research, and other material resource
use need explicit bounds before consumption. When a limit exists, count usage
across retries/workers and reconcile unfinished jobs before spending more;
unknown usage is not zero, and a new attempt does not reset the allowance.
Stop repeating a failing approach without new evidence; investigate the cause or
report the missing decision. Apply the [local blocker rule](../SKILL.md#scope-and-authority).

Internal edits and tests need no separate reports or frozen checks. Review breadth
follows risk; another reviewer is optional. After relevant changes, rerun affected
verification instead of merely relabeling an earlier result.

The same worker can continue the same assignment after return. Retain each formal
delivery's inputs, outputs, and report at a distinct retrievable version/location;
use a new delivery revision, not a new dispatch, for ordinary continuation. Never
overwrite a received version or its evidence. Identical replay of that version is
a no-op; changed content under the same version needs investigation. Reassignment
or retry that may overlap old execution needs a new attempt and a stopped/fenced
old writer; see [collection and recovery](parallel-handoff.md#manager-collect-and-recover).

Acceptance or a changed acceptance decision needs a new scoped check, preserving
old checks and evidence—even for `pass` → `pass` after inspected inputs change.
Use existing project review records; bundled schema 2 uses a new check file.

For [research](research.md), repair invalid execution within the authorized method
and recomputation budget. A valid negative or inconclusive finding is not a defect;
additional experiments or changed metrics need a justified, authorized decision.
